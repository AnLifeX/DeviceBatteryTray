# 雷神 ML903 mini 鼠标（星闪接收器）电量协议

> 来源：ML903-NearLink Driver 自带的通讯日志 `logs/Iton_HIDMOU_Com_x86/*.log`（方案商 ITON），已在本机实测验证（2026-11-24）。

## 设备识别
| 项 | 值 |
|---|---|
| 星闪接收器 | `369B:0114`（`ML903mini NearLink`，序列号 DG…） |
| 有线直连 | `369B:00F3`（序列号 MS…） |
| 通讯接口 | UsagePage `0xFFA0`，Usage `0x02`，输出 Report ID `0xA0`，输入 Report ID `0xA1`，64 字节 |

驱动同时支持 PID `0113/0134/0023/0024/00F3/0114/00C1/01C4/01E3/0234`（同一方案的其它雷神鼠标），协议应相同。

## 查询状态（report_device_status, 0x50）
发送：`A0 50 00 00 …`（补 0 到 64 字节）

回包：
```
A1 50 01 03 0D 02 04 25 5F 44 03 02 02 06 04 01 00 06 …
      │                 └─ 25 后面这个字节 = 电量
      └─ 01 = 鼠标在线；00 且后面全 0 = 鼠标离线/休眠
```
电量字节：
- 低 7 位 = 百分比（0x5F = 95%，0x64 = 100%）
- 最高位 = 充电中（有线直连时见到 `0xBC` = 充电中 + 60%）

实测：`… 25 5F …` → 95%，未充电。

### 充电状态（2026-11-28 / 11-29 实测）
- **只有有线直连（`00F3`，`rx[2]=02`）时最高位会置位**，但实测（含驱动长达数小时的历史日志）表明：**有线模式下鼠标固件永远固定返回 `0xBC`（充电中 + 60%），不上报真实电量百分比**。
- **经星闪接收器（`0114`）读取时永远不置位**：放在充电底座上充电（鼠标指示灯亮着）读到的仍是 `25 35`（53%），
  整包与未充电时只差电量字节；驱动日志里一段经接收器 9% → 94% 的充电过程也从未出现最高位。
  底座只供电，电脑上看不到额外的 USB 设备；厂商驱动也只发 `0x50` 这一个命令、没有充电图标，同样显示不了。
- 所以接收器模式下程序按电量走势推断充电（`Devices/ChargeTrend.cs`）：对最近 15 分钟的读数做线性回归，
  斜率 ≥ +0.15%/分钟判定充电中；斜率 ≤ -0.05%/分钟或未满时 30 分钟不再上涨判定未充电。
  不能只看"比最低点高 2%"：放电时单次读数会在 ±1~2% 之间来回跳（如 82 → 84 → 83）。
  用驱动日志里 716 个经接收器的放电读数回放，误报 0 次；开始充电约 10 分钟后才会显示充电（放在底座上不适用，见下）。
- 回包里 `44 03 xx` 的 `xx` 会在 01~04 之间变化，那是**当前 DPI 档位**（驱动下发 `44 2c 0N` 后随之变化），与充电无关。

## 备注
- 解析时用「找到 tag `0x25` 取下一字节」，不要写死偏移（前面的 TLV 可能随固件变化）。

### 放在充电底座上（2026-11-28 实测）
- 鼠标在底座上**不再向接收器上报**：接收器一直返回最后缓存的电量（如 00:16~00:28 恒为 65%），拿下来瞬间跳到实际值（66% → 70%）。
  回包其余字节与平时完全相同，被动监听也收不到任何主动上报，所以**经接收器无法实时判断是否在底座上充电**。
- "读数长时间不变"不能当充电依据：放在桌上未充电时也常见 10~20 分钟读数不变。
- 上面的走势推断只对"接收器模式下边用边充"（如插充电头）有效，在底座上不会触发。

### 接收器 + 数据线同时插着
两边同时在线时，因为有线模式只返回固定 `0xBC`（60%），程序优先保留星闪接收器读到的真实电量百分比，只借用有线的充电标志与有线连接状态（若接收器已休眠/断开才退回有线读数），仍归在接收器名下。只有一个接收器时才这样合并。
